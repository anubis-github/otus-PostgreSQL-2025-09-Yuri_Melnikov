0. Создаем новую ВМ с параметрами как в предыдущем задании и заново ставим Postgres

```shell
# создаем ВМ через cli Я.Облако
yc compute instance create \
  --name otus-postgres-hw10-1 \
  --hostname otus-postgres-hw10-1 \
  --cores 2 \
  --core-fraction 50 \
  --memory 2 \
  --create-boot-disk size=10G,type=network-hdd,image-folder-id=standard-images,image-family=ubuntu-2404-lts \
  --network-interface subnet-name=default-ru-central1-b,nat-ip-version=ipv4 \
  --ssh-key ~/.ssh/ssh-key-postgres.pub
```

```shell
# Ставим Postgres, пользуясь apt
yc-user@otus-postgres-hw10-1:~$ sudo apt update && sudo apt upgrade -y -q && \
sudo sh -c 'echo "deb http://apt.postgresql.org/pub/repos/apt $(lsb_release -cs)-pgdg main" > /etc/apt/sources.list.d/pgdg.list' && \
wget --quiet -O - https://www.postgresql.org/media/keys/ACCC4CF8.asc | sudo apt-key add - && \
sudo apt-get update && \
sudo apt -y install postgresql

# Проверяем что кластер запущен
yc-user@otus-postgres-hw10-1:~$ sudo pg_lsclusters
Ver Cluster Port Status Owner    Data directory              Log file
18  main    5432 online postgres /var/lib/postgresql/18/main /var/log/postgresql/postgresql-18-main.log
```

5. Создать индекс на несколько полей

> Создаем индекс на поля ```name``` и ```author```
```
books=# create index on books using btree(name, author);
CREATE INDEX
books=# \d books
                                    Table "public.books"
      Column      |     Type      | Collation | Nullable |             Default
------------------+---------------+-----------+----------+----------------------------------
 id               | integer       |           | not null | generated by default as identity
 name             | character(50) |           |          |
 author           | character(50) |           |          |
 publication_date | date          |           |          |
 description      | text          |           |          |
 tsv_description  | tsvector      |           |          |
Indexes:
    "books_pkey" PRIMARY KEY, btree (id)
    "books_name_author_idx" btree (name, author)
    "books_name_idx" btree (name) WHERE author = ANY (ARRAY['Автор 2'::bpchar, 'Автор 4'::bpchar, 'Автор 6'::bpchar, 'Автор 8'::bpchar, 'Автор 10'::bpchar, 'Автор 12'::bpchar])
    "books_tsv_description_idx" gin (tsv_description)
```
> Проверяем планы запросов с использованием колонок ```name``` и ```author``` в условии запроса в разных сочетаниях чтобы убедиться что БД использует индекс
```
books=# explain select name, author from books where name = 'Книга 1' and author = 'Автор 1';
                                         QUERY PLAN
---------------------------------------------------------------------------------------------
 Index Only Scan using books_name_author_idx on books  (cost=0.29..10.97 rows=334 width=112)
   Index Cond: ((name = 'Книга 1'::bpchar) AND (author = 'Автор 1'::bpchar))
(2 rows)

books=# explain select name, author from books where name = 'Книга 1';
                                          QUERY PLAN
----------------------------------------------------------------------------------------------
 Index Only Scan using books_name_author_idx on books  (cost=0.29..91.17 rows=4050 width=112)
   Index Cond: (name = 'Книга 1'::bpchar)
(2 rows)

books=# explain select name, author from books where author = 'Автор 1';
                                          QUERY PLAN
-----------------------------------------------------------------------------------------------
 Index Only Scan using books_name_author_idx on books  (cost=0.29..122.69 rows=4050 width=112)
   Index Cond: (author = 'Автор 1'::bpchar)
(2 rows)
```

> Во всех вариантах используется индекс ```books_name_author_idx```, как и ожидалось

> Так же видно, что если индекс есть только на одну из колонок в условии запроса, а на другую нет, то планировщик все равно использует индекс
```
books=# explain select name, author from books where name = 'Книга 1' and description = 'Автор 1';
                                       QUERY PLAN
----------------------------------------------------------------------------------------
 Bitmap Heap Scan on books  (cost=50.67..1601.42 rows=1 width=112)
   Recheck Cond: (name = 'Книга 1'::bpchar)
   Filter: (description = 'Автор 1'::text)
   ->  Bitmap Index Scan on books_name_author_idx  (cost=0.00..50.66 rows=4050 width=0)
         Index Cond: (name = 'Книга 1'::bpchar)
(5 rows)

books=# explain select name, author from books where author = 'Автор 1' and description = 'Книга 1';
                                       QUERY PLAN
----------------------------------------------------------------------------------------
 Bitmap Heap Scan on books  (cost=82.19..1632.94 rows=1 width=112)
   Recheck Cond: (author = 'Автор 1'::bpchar)
   Filter: (description = 'Книга 1'::text)
   ->  Bitmap Index Scan on books_name_author_idx  (cost=0.00..82.19 rows=4050 width=0)
         Index Cond: (author = 'Автор 1'::bpchar)
(5 rows)
```
